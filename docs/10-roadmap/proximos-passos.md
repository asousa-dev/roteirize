## 33.1 Antes de programar

1. Confirmar ou trocar o nome provisório.
2. Revisar o escopo do MVP.
3. Escolher um caso demonstrativo de cidade.
4. Desenhar fluxos de baixa fidelidade.
5. Escolher o primeiro provedor de lugares e rotas.
6. Fixar versões da stack.
7. Criar o repositório.
8. Transformar o backlog em issues.

## 33.2 Primeira entrega técnica recomendada

Não começar pelo algoritmo.

A primeira entrega deve ser:

- repositório;
- frontend exibindo uma tela inicial;
- backend respondendo um endpoint de saúde;
- PostgreSQL local;
- pipeline básico;
- README com instruções.

Depois:

- autenticação;
- viagens;
- atrações;
- planejamento manual;
- somente então geração automática.

## 33.3 Perguntas abertas

Estas decisões não bloqueiam a documentação, mas devem ser resolvidas antes das etapas correspondentes:

- Qual será o nome definitivo?
- O primeiro modo será caminhada, carro ou ambos?
- Qual provedor será usado no desenvolvimento?
- A hospedagem será obrigatória?
- A pausa de almoço será um bloco fixo ou uma preferência?
- A programação deve sempre retornar à hospedagem?
- A primeira geração será síncrona ou já terá consulta de progresso?
- Qual identidade visual o produto terá?
- A colaboração entrará imediatamente após o MVP?
