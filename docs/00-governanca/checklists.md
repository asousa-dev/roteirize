## Apêndice B — Checklist para uma issue

~~~markdown
## Objetivo

Descreva o resultado esperado.

## História

Como [papel], quero [ação], para [benefício].

## Critérios de aceitação

- [ ] Critério observável 1
- [ ] Critério observável 2
- [ ] Estado de erro tratado
- [ ] Autorização verificada
- [ ] Testes adicionados

## Fora do escopo

Liste o que não será feito nesta issue.

## Como validar

Passos manuais e testes automatizados.
~~~

## Apêndice C — Checklist de revisão de pull request

- [ ] A mudança resolve a issue.
- [ ] Os nomes estão claros.
- [ ] Não há regra crítica somente no frontend.
- [ ] Autorização foi verificada.
- [ ] Erros possuem códigos seguros.
- [ ] Datas e fusos foram tratados corretamente.
- [ ] Alterações de banco possuem migração.
- [ ] Integrações possuem timeout.
- [ ] Não existem chaves ou segredos.
- [ ] Testes relevantes passam.
- [ ] Interface possui estados de carregamento, vazio e erro.
- [ ] Documentação foi atualizada.
