## Finalidade

Esta documentação é a fonte principal de verdade do projeto enquanto não houver uma decisão mais recente registrada. Ela descreve o produto, os requisitos, as regras, o algoritmo, os dados, a arquitetura e o plano de desenvolvimento.

## Organização

Cada pasta representa um domínio documental. A numeração estabelece uma ordem de leitura, não uma dependência técnica.

## Regras de atualização

- Alterações funcionais devem atualizar requisitos e regras relacionados.
- Mudanças de arquitetura devem atualizar o documento técnico e a decisão correspondente.
- Novas funcionalidades devem entrar primeiro no backlog e no escopo da versão adequada.
- IDs de requisitos e regras não devem ser reutilizados.
- Conteúdo removido deve ser registrado no histórico quando a mudança for relevante.
- O README da documentação deve continuar apontando para todos os documentos ativos.

## Estado atual

A documentação define uma arquitetura e um escopo de referência. Tecnologias, provedores externos e detalhes de interface ainda podem ser revisados antes da implementação.
